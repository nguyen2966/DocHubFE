Update the PDF viewer behavior: disable zoom completely to stabilize React avatar markup rendering.

Context:
Avatar markup rendering became unstable because zoom changes require repeated projection/recalculation from PDF page coordinates into overlay coordinates. The current stable visual behavior is achieved at one fixed viewer scale. To reduce complexity and improve reliability, we now want to disable zoom in the PDF viewer.

Goal:

* User must not be able to zoom in/out.
* PDF should render at one stable scale.
* Avatar markup should be rendered relative to the PDF page at that stable scale.
* Avatar markup should still behave like page-bound markup:

  * attached to a specific page
  * scrolls away with that page
  * disappears naturally when its page scrolls out of view
  * reappears when scrolling back
* No zoom recalculation complexity is needed anymore.

Scope:

* FE only.
* Do not modify BE.
* Do not change API payload shape.
* Do not change comment data model.
* Keep native Apryse highlight rendering from XFDF.
* Keep visualState authoritative over xfdf.
* Do not use Apryse StampAnnotation for avatar markers.
* Avatar marker should remain React-rendered markup.
* CommentThreadPopover remains React fixed UI panel.
* SelectionCommentAction should still work.

Files to inspect/update:

* src/features/documents/components/details-page/AprysePdfViewer.tsx
* src/features/comments/components/CommentAnnotationOverlayLayer.tsx
* src/features/comments/components/CommentAnchorMarker.tsx
* src/features/documents/components/details-page/DocumentViewerShell.tsx
* src/pages/document-details/DocumentDetailPage.tsx

Main requirement:
Disable all user zoom paths in Apryse WebViewer.

This includes:

1. Hide/remove zoom UI controls if present.
2. Disable toolbar zoom in/out controls if present.
3. Disable mouse wheel zoom / Ctrl + wheel zoom.
4. Disable keyboard zoom shortcuts:

   * Ctrl/Cmd + +
   * Ctrl/Cmd + -
   * Ctrl/Cmd + 0
5. Disable pinch zoom if WebViewer exposes a supported API for it.
6. Avoid fit modes that dynamically change zoom after initial render, unless absolutely necessary.

Preferred viewer scale:

* Use one fixed zoom level after document loaded.
* Prefer a stable explicit zoom level such as 1.0 / 100%, or the current stable default if the app already sets one.
* Do not allow user interaction to change it afterward.
* If current viewer uses FitWidth/FitPage and that causes scale changes on resize, replace it with explicit zoom.
* If exact 100% makes the PDF layout poor, choose one fixed project constant, e.g. DEFAULT_PDF_ZOOM = 1.0 or DEFAULT_PDF_ZOOM = current stable value, but keep it constant.

Implementation guidance in AprysePdfViewer.tsx:

1. Add constants:

const LOCKED_PDF_ZOOM = 1
const ZOOM_LOCK_ENABLED = true

2. After document is loaded, enforce locked zoom:

* call the proper Apryse API to set zoom level to LOCKED_PDF_ZOOM.
* do this once after documentLoaded.
* also guard against later zoom changes if Apryse still emits zoomUpdated.

Pseudo:

const enforceLockedZoom = () => {
const instance = instanceRef.current
if (!instance) return

const { documentViewer } = instance.Core

const currentZoom = documentViewer.getZoomLevel?.()
if (currentZoom !== LOCKED_PDF_ZOOM) {
documentViewer.setZoomLevel?.(LOCKED_PDF_ZOOM)
}
}

3. On zoomUpdated:

* if zoom differs from LOCKED_PDF_ZOOM, immediately restore LOCKED_PDF_ZOOM.
* avoid infinite loops with a ref:

const isEnforcingZoomRef = useRef(false)

Pseudo:
if (isEnforcingZoomRef.current) return
if (currentZoom !== LOCKED_PDF_ZOOM) {
isEnforcingZoomRef.current = true
documentViewer.setZoomLevel(LOCKED_PDF_ZOOM)
requestAnimationFrame(() => {
isEnforcingZoomRef.current = false
})
}

4. Remove/hide zoom controls from Apryse UI.

Inspect current Apryse UI setup and disable/remove:

* zoomOverlayButton
* zoomInButton
* zoomOutButton
* zoom controls in header/toolbars
* fit mode controls if they allow changing zoom
* any hotkeys if configured

Use Apryse UI APIs already used in this file, e.g. disableElements/hideElements if available.

Do not break:

* page navigation buttons
* content edit button
* comment button
* share button
* selection/comment interaction

5. Block browser/input zoom events inside viewer wrapper.

At the viewer wrapper level:

* add wheel listener with passive: false.
* if event.ctrlKey or event.metaKey is true, preventDefault and stopPropagation.
* add keydown listener:

  * Ctrl/Cmd + '+'
  * Ctrl/Cmd + '-'
  * Ctrl/Cmd + '='
  * Ctrl/Cmd + '0'
    should preventDefault when focus is inside viewer/document area.

Do not block normal scrolling without Ctrl/Cmd.
Scrolling must still work.

6. Simplify avatar marker recomputation.

Since zoom is locked:

* Marker overlay should not need complex zoom recalculation.
* Still compute marker position from pageNumber + PDF page coordinate.
* Still recompute on:

  * document loaded
  * commentThreads change
  * scroll
  * page change
  * viewer resize if needed
  * sidebar visibility change
* But do not support arbitrary zoom changes.
* If zoomUpdated happens, enforce locked zoom and then recompute markers once.

7. Avatar marker behavior.

Avatar marker should be React-rendered page-bound markup:

* not Apryse StampAnnotation
* not viewport fixed
* not global floating UI
* belongs to a pageNumber
* uses page coordinate as source of truth
* rendered in overlay relative to viewer/page projection at the locked zoom

When user scrolls:

* marker moves with page content.
* if its page scrolls out of viewport, marker disappears naturally.
* when scrolling back, marker appears again.

8. Sidebar visibility.

Use existing showCommentAvatarMarkers prop:

* DocumentDetailPage passes showCommentAvatarMarkers={!commentsOpen}
* DocumentViewerShell forwards it
* AprysePdfViewer receives it

When showCommentAvatarMarkers is false:

* no React avatar markers render.
* highlights may remain visible.

When showCommentAvatarMarkers is true:

* render markers again from commentThreads/page coordinates.

9. Remove obsolete StampAnnotation marker logic.

If previous implementation still has native avatar StampAnnotation logic:

* do not create avatar StampAnnotations anymore.
* keep one-time cleanup for legacy docHubKind === "avatar-marker" annotations if necessary.
* remove export-specific cleanup that only existed for avatar StampAnnotations unless needed for legacy cleanup.

10. Click behavior.

When user clicks avatar marker:

* do not call Apryse selectAnnotation.
* do not call highlightCommentAnnotation.
* do not call documentViewer.refreshAll/updateView.
* compute popover position from marker DOM rect:

const rect = markerElement.getBoundingClientRect()
const clientPosition = {
x: rect.right,
y: rect.top + rect.height / 2,
}

* call existing onCommentAnnotationClick callback with annotationId and clientPosition.

11. Native highlight click behavior.

When user clicks native DocHub highlight:

* get docHubAnnotationId.
* prefer opening popover near the corresponding React avatar marker DOM rect.
* fallback to projected page anchor if marker DOM is unavailable.
* do not use generic viewer-left fallback for anchor mode.
