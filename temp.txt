Implement Phase 1: Convert comment avatar marker rendering from React overlay to Apryse native annotation.

Scope:

* FE only.
* Do not modify BE.
* Do not change API payload shape.
* Do not change comment thread data model.
* Do not change DocumentDetailPage anchor-mode positioning yet; that is Phase 2.
* Do not rewrite the whole Apryse viewer.
* Apply targeted changes.

Goal:
Currently comment avatar markers are rendered as React fixed overlays through CommentAnnotationOverlayLayer / CommentAnchorMarker. This is unstable because marker position depends on client coordinate conversion, scroll, zoom, and Apryse internal layout.

Replace avatar marker rendering with an Apryse-managed annotation, preferably StampAnnotation using an existing image asset from the FE asset folder.

Expected result:

1. Existing highlight comments still render native Apryse highlight from XFDF.
2. Each comment thread also renders an Apryse avatar marker annotation.
3. Avatar marker appears to the right side of the comment highlight annotation.
4. When annotation.visualState === "point", FE must not import stale XFDF highlight, but avatar marker must still render at annotation.position.
5. Avatar marker should be part of Apryse annotation layer, so it follows PDF page coordinate, zoom, scroll, page change, and fit mode automatically.
6. React CommentAnchorMarker overlay should no longer be used for persisted comment avatar markers.
7. Add Comment button for new text selection should stay as React overlay for now.
8. Comment composer / CommentThreadPopover can stay React. Phase 2 will refine popover position.

Important existing behavior to preserve:

* visualState remains authoritative over xfdf.
* If visualState === "point", skip XFDF import even if xfdf still exists.
* If visualState === "highlight" and xfdf exists, import XFDF highlight.
* Avatar marker should render in both highlight and point states.
* Do not reintroduce native ellipse/rectangle point markers.
* Avatar marker must not be persisted to BE.
* Avatar marker must not be baked/exported into the edited PDF.

Files to inspect:

* src/features/documents/components/details-page/AprysePdfViewer.tsx
* src/features/comments/components/CommentAnnotationOverlayLayer.tsx
* src/features/comments/components/CommentAnchorMarker.tsx

* existing assets under src/assets or equivalent asset folder

Implementation details:


1. Add DocHub-managed annotation custom data constants in AprysePdfViewer.tsx.

Use custom metadata like:

* docHubManaged = "true"
* docHubKind = "comment-highlight" | "avatar-marker" | "pending-comment-highlight"
* docHubAnnotationId = Mongo annotation/thread id
* docHubApryseRole = optional

The goal is to distinguish:

* imported DocHub comment highlights
* temporary pending highlights
* DocHub avatar marker stamp annotations
* unrelated user annotations

2. Use Apryse StampAnnotation for avatar marker.

Create helper:
createAvatarMarkerAnnotation(params)

Input:

* threadId: Mongo annotation id
* pageNumber
* anchor page coordinate: { x, y }

Behavior:

* Create new Annotations.StampAnnotation.
* Set PageNumber.
* Set X/Y/Width/Height in Apryse page coordinate.
* Use image asset as ImageData.
* Set custom data as DocHub avatar marker.
* Make it read-only / non-movable / non-resizable / non-deletable if supported by Apryse.
* Make it non-listable if supported.
* The marker is purely visual/clickable FE annotation.

Suggested placement:

* For highlight state:
  marker should be right side of the rendered highlight.
* For point state:
  marker should be derived from annotation.position.

Suggested constants:

* AVATAR_MARKER_WIDTH
* AVATAR_MARKER_HEIGHT
* AVATAR_MARKER_GAP

These are PDF page units, not CSS px. Pick conservative values and make them easy to tune.

3. Load image asset safely.

If StampAnnotation needs base64/data URL:

* Convert imported asset URL to data URL once.
* Cache it in a ref.
* Avoid re-fetching image for every thread.

Example helper shape:
getAvatarMarkerImageData(): Promise<string>

4. Render flow in renderCommentThreads().

Before rendering:

* Remove all existing DocHub-managed comment visual annotations from Apryse:

  * imported DocHub comment highlights
  * old DocHub avatar marker stamps
  * stale temporary pending anchors when appropriate
* Do not delete unrelated user annotations.

Then for each thread:

* Skip deleted annotations.
* Compute normalized visual state:
  visualState = annotation.visualState ?? (annotation.xfdf ? "highlight" : "point")

Case A: visualState === "highlight" and annotation.xfdf exists:

* Import annotation.xfdf using annotationManager.importAnnotations.
* Mark imported annotation(s) as DocHub comment highlight using custom data.
* Set docHubAnnotationId to annotation._id.
* Make imported highlight read-only if appropriate.
* Derive avatar anchor from the imported highlight geometry:
  anchor.x = importedHighlight.X + importedHighlight.Width
  anchor.y = importedHighlight.Y + importedHighlight.Height / 2
* If imported geometry is unavailable, fallback to annotation.position.

Case B: visualState === "point":

* Do not import annotation.xfdf.
* Derive avatar anchor from annotation.position:
  anchor.x = annotation.position.x
  anchor.y = annotation.position.y

Case C: visualState === "highlight" but xfdf missing:

* Do not import highlight.
* Still render avatar marker from annotation.position if position exists.

For every thread with a valid anchor:

* Create one avatar marker StampAnnotation.
* Add it to annotationManager.
* Redraw it.

5. Disable React overlay avatar markers.

Persisted comment avatar markers should no longer render via CommentAnchorMarker.

Options:

* In AprysePdfViewer, stop populating commentMarkerOverlays for persisted thread markers.
* Or pass markers={[]} to CommentAnnotationOverlayLayer.
* Keep SelectionCommentAction for "Add comment" text selection.
* Do not remove CommentAnchorMarker component from the project yet unless it becomes fully unused and TypeScript confirms safe deletion.
* Avoid duplicate avatar markers: there must not be both React avatar marker and Apryse stamp marker.

6. Annotation click handling for avatar markers.

In annotationSelected listener:

* Detect if selected annotation is DocHub avatar marker.
* Read docHubAnnotationId.
* Call onCommentAnnotationClickRef.current(annotationId, clientPosition).

For Phase 1, clientPosition can be computed from the marker annotation geometry using existing conversion helper:

* page point = { x: marker.X + marker.Width, y: marker.Y + marker.Height / 2 }
* convert with pageToWindow + normalizeAprysePointToClient
* pass that client position to the existing parent callback.

Do not redesign anchor popover positioning yet. Phase 2 will refine DocumentDetailPage / anchor mode positioning. This phase only needs marker clicks to keep working reasonably.

For selected DocHub highlight annotation:

* Existing behavior can remain, but preferably if there is a matching avatar marker annotation, use the avatar marker geometry for clientPosition.
* Do not spend large refactor effort here in Phase 1.

8. Prevent avatar marker from being exported into edited PDF.

Because avatar marker is now an Apryse annotation, it must not be saved into the PDF file.

Before exportEditedPdf or any full PDF export:

* Temporarily remove DocHub avatar marker stamp annotations.
* Export the edited PDF.
* Re-render comment threads afterwards to restore avatar markers.

Be careful:

* Do not remove actual comment highlights that should remain in PDF editing flow unless existing logic already does so intentionally.
* Avatar marker stamps are UI-only and must never be baked into the exported PDF.
